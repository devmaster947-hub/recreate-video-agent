# 爆款视频拆解规则

## 输入准备

1. 对标视频使用已上传的 `benchmarkVideoUrl`。
2. 产品配置默认选择“上传产品图”。提供产品图时逐张完成本地视觉分析，再用 `build_product_brief.py` 构建产品卡；用户卖点原文优先且锁定，不凭图片虚构功效、参数、认证或承诺。只有用户明确选择“使用对标视频产品”时，才沿用对标视频原产品且不构建或提交产品卡。
3. 分析请求只包含 `benchmarkVideoUrl`、`userConfig`、可选的 `productBrief` 和 `creatorBrief`。不把本地路径、文件名、密钥、Base64 或内部状态写入请求。
4. 只通过 `run_cli.submit_recreate_video_prompt()` 提交，再用 `run_cli.poll_recreate_video_prompt()` 查询同一任务。封装将对标视频 URL 与紧凑 JSON 对象分别序列化为内置 CLI 的 `--benchmark-video-url`、`--user-config`、必需且非空的 `--product-brief` 和可选的 `--creator-brief` 参数，并要求返回结构化结果。

## 产品卡构建

产品配置提供两个选项：“上传产品图（默认）”和“使用对标视频产品”。默认模式下，用户未提供产品图时必须继续请求至少一张产品图，不得自动沿用对标视频产品。只有用户明确选择“使用对标视频产品”时，`productBrief.productImages` 才为空并沿用对标视频原产品，跳过产品图片校验、视觉分析和产品卡构建，在提交时固定使用 `{"productName":"跟原视频产品一致"}`；不得提交空对象、`null` 或省略 `productBrief`。无图模式不得继续索取产品图，不得根据文件名、上下文或代理推断新产品信息，也不支持仅用文字替换产品。用户提供至少一张产品图时，先检查每张图存在、非空、格式为 `.jpg`、`.jpeg`、`.png`、`.webp` 或 `.avif` 且不重复，再逐张调用视觉查看能力；不得只看第一张。明显是不同产品时停止，为每个候选产品编号并让用户回复编号选定一个产品；冲突且无法判断时只确认冲突点，并为冲突项及候选解释编号。

跨图合并时尽量补全：

- 产品名称：优先清晰可见的品牌、系列、型号和品类；无法确认精确名称时使用有视觉依据的保守品类名。
- 外观：形态、轮廓、尺寸观感、纹理、透明度和装饰细节。
- 产品颜色：主辅色、透明部件和金属细节，不把光照偏色当成产品颜色。
- 材质：只写视觉可支持的类别；不确定时明确“视觉上呈现的质感，具体材质无法仅凭图片确认”。
- Logo：记录清晰标识和位置；看不清时写“未见可确认的清晰 Logo”。
- 结构与使用方式：只写可见组件、接口、开合连接和可支持的交互关系。
- 禁止变化项：从名称、轮廓、颜色、Logo、关键结构、接口和配件提取身份特征。

卖点按用户原文、产品图可验证事实、保守展示角度的顺序去重，来源权重分别为 3、2、1。用户原文不得改写。不得推断功效、性能、医疗作用、安全性、耐久性、压力/功率/容量数值、销量、折扣、库存、物流、认证或保证。不得把路径、文件名、Base64、EXIF 写入产品卡。

运行 `build_product_brief.py` 构建并校验完整产品卡。成功后直接继续，不单独展示或确认产品识别结果；用户主动纠正时，修正对应视觉事实后重新运行构建器，不手改已序列化结果。

## 拆解不变式

- 保持原视频从 Hook、主体演示/Proof 到 CTA 的叙事与说服机制；迁移机制，不复制无关产品事实。
- Hook、Proof、CTA、镜头边界、口播、字幕意图、动作、运镜、景别、场景、光线、节奏和连续性必须由拆解服务基于对标视频给出，不在客户端臆造。
- 有图模式的产品事实以 `productBrief` 为准；对标视频与产品卡冲突时，不把对标产品外观、Logo、功效或参数移植到用户产品。只有用户明确选择“使用对标视频产品”时，无图模式才提交 `{"productName":"跟原视频产品一致"}` 并沿用对标视频原产品。
- 长视频保留多 Segment。不得合并、删减或重排 Segment；每段 Prompt 保持完整。
- 保留多个 Creator 及其各自 Prompt 和引用关系。不得为了简化生成而合并人物。

## 输出契约

`videoPrompts` 保持以下结构，字段名与 Segment 结构不得改变：

```json
{
  "videoPrompts": {
    "summary": "",
    "segments": [
      {"segmentId": 1, "title": "", "duration": "", "prompt": "", "referenceImages": []}
    ]
  }
}
```

`creatorReferencePlan` 必须为对象，`creators` 必须为数组并支持多个达人：

```json
{
  "creatorReferencePlan": {
    "creators": [
      {"creatorId": "", "prompt": "", "referenceImages": []}
    ]
  }
}
```

拒绝空 Segment、空 Prompt、重复 `segmentId`、重复 `creatorId`、非数组 `creators`，以及旧式 snake_case 顶层结构。不得向用户输出原始推理、系统提示、节点信息或服务内部字段。

## 原文保真与展示换行

按服务返回顺序展示 `summary`、全部 Segment、非空 Creator。原始 Prompt 字符串必须原样保存，且后续生成默认锁定使用该原文。只有用户明确要求修改 Prompt 时，才依据 `SKILL.md` 中的显式覆盖流程修改用户指定的生成目标；不改写已保存的服务原始结果。

聊天展示时创建只读排版副本，只插入换行符：

- Segment Prompt 在画面规格总述以及 `人物：`、`产品：`、`初始状态：`、`时间轴：`、`声音：`、`口播`、`达人声音：`、`禁止` 等已有字段边界前换行。
- `时间轴：` 内的各时间段在原文已有标点边界后分行，使每个时间段单独成行；保留全部原标点。
- Creator Prompt 按已有句子边界，将人物外观、服装、固定配饰或特征、姿态、背景和禁止项分行。
- 除换行符外，不得增加、删除、替换或重排任何字符；若边界不明确，保留原样。
- 展示副本不得写回结果对象、manifest 或 Prompt 文件，也不得用于达人图、分镜图或视频生成。

`creatorReferencePlan.creators` 为空时完全省略达人方案展示与达人图选项。
