# product_brief 产品卡生成

仅在用户已明确选择“替换为新产品”且提供了新产品图时读取本文件。不得根据无图状态自动决定沿用，也不得因为附件中有产品图就自动决定替换。用户明确选择“沿用对标视频产品”时，设置`product.useBenchmarkProduct=true`并跳过产品卡生成。用户选择替换且提供产品图时，用户输入仅包含图片和可选卖点，不询问可从图片观察的名称、外观、颜色、材质、Logo、结构或使用方式。

## 1. 输入与图片校验

- 用户提供新产品图后，`product.productImages`必须至少包含一张图片。
- 用户明确选择沿用对标视频原产品时，`product.productImages`为空数组并跳过本文件后续图片校验、视觉分析和产品卡构建。
- 接受 `.jpg`、`.jpeg`、`.png`、`.webp`、`.avif` 静态图片。
- 用户提供至少一张产品图时，先确认文件存在、非空且不重复，不执行上传。
- 无图模式不得根据文件名、上下文或代理推断新产品，也不得把文字描述转换成替换产品卡。

仅在有产品图时运行（单行执行，重复 `--image` 参数）：

- macOS：`python3 scripts/validate_product_images.py --image <product-1> --image <product-2>`
- Windows PowerShell：`py -3 scripts/validate_product_images.py --image <product-1> --image <product-2>`

## 2. 必须执行的本地视觉分析

有产品图且校验通过后，对每张产品图逐张调用 `view_image`，然后跨图合并为一张产品卡。不得只看第一张，不得跳过视觉分析直接生成空卡或中性占位卡。无图模式不得调用 `view_image`，也不得生成空卡或中性占位卡。

先判断多图是否为同一产品：

- 同一产品的不同角度、包装、配件或使用示意：继续合并。
- 明显是不同产品：停止，为每个候选产品编号并请用户回复编号选定一个产品，不得混成一张产品卡。
- 图片互相冲突且无法判断时，仅就冲突点请用户确认；每个冲突点和候选解释都必须编号。

按以下规则尽量补全：

- `产品名称`：优先读取包装或产品上清晰可见的品牌、系列、型号和品类。无法确认精确商品名时，使用可见特征支持的保守品类名，不得编造型号。
- `外观`：形态、轮廓、尺寸观感、表面纹理、透明度和装饰细节。
- `产品颜色`：主色、辅色、透明部件和金属色细节；不把光照偏色当成产品颜色。
- `材质`：只写视觉上可支持的材质类别。无法确认具体材料时，使用“视觉上呈…质感，具体材质无法仅凭图片确认”，不得猜测精确材料型号。
- `Logo`：记录清晰可见的品牌文字、图形标识及位置。看不清时写“未见可确认的清晰 Logo”，不得猜测。
- `结构`：可见组件、按键、开口、接口、开合方式、连接关系、随附配件和可拆部件。
- `使用方式`：根据可见结构、包装图示或使用场景说明操作关系。无法确认完整步骤时，只写可见的交互方式。
- `产品卖点`：用户卖点原文在前，然后加入从产品图可直接支持的设计、结构、便携性、收纳性或使用便利特征。
- `用户卖点锁定`：与用户提供的产品卖点原文完全一致；未提供时为空数组。
- `禁止变化项`：从产品名称、轮廓、颜色、Logo、关键结构、接口和配件中提取视频生成时必须保持不变的身份特征。

目标是最小化空字符串，但必须区分“可见事实”与“无法仅凭图片确认”。不得为了填满字段而虚构信息。

## 3. 卖点来源与安全边界

产品卖点按以下顺序保存并去重：

1. `user_selling_points`：用户卖点原文，不改写，`source=user`、`authority=3`。
2. `product_material_facts`：产品图可直接支持的产品特征，`source=product_material`、`authority=2`。
3. `ai_supplements`：不新增产品承诺的保守展示角度，`source=ai_supplement`、`authority=1`。

可以从图中读取清晰可见的包装文字，但不得将难以辨认的文字补全成事实。禁止无依据推断或强化功效、性能、医疗作用、安全性、耐久性、压力/功率/容量等数值、销量、折扣、库存、物流、认证或保证。

不得把图片路径、文件名、Base64、`data:image`、EXIF 或本地目录写入任何字段。

## 4. 构建完整产品卡

有产品图时，将本地视觉分析结果写入 manifest 的 `product.productAnalysis`，并用以下本地构建器完成校验与序列化。用户明确选择“使用对标视频产品”后，无图模式保持空 `productAnalysis`，并将产品名称记为“跟原视频产品一致”。不得生成空占位产品卡。

```text
scripts/build_product_brief.py --product-name "<从产品图识别的名称或保守品类名>" --appearance "<外观>" --product-color "<产品颜色>" --material "<材质或带不确定边界的视觉判断>" --logo "<Logo 及位置，或未见可确认的清晰 Logo>" --structure "<结构>" --usage "<使用方式>" --user-selling-point "<用户卖点原文，可重复>" --product-material-fact "<产品图可验证的卖点，可重复>" --ai-supplement "<保守展示角度，可重复>" --forbidden-change "<禁止变化项，可重复>" --compact
```

- macOS：在上述单行命令前加 `python3 `。
- Windows PowerShell：在上述单行命令前加 `py -3 `。

用户未提供卖点时省略 `--user-selling-point`，但必须至少有一条经视觉分析确认的 `--product-material-fact`，不得恢复固定中性占位卖点。

工具输出固定为：

```json
{
  "产品卡": {
    "产品名称": "",
    "外观": "",
    "产品颜色": "",
    "材质": "",
    "Logo": "",
    "结构": "",
    "使用方式": "",
    "产品卖点": [
      {
        "text": "",
        "source": "user/product_material/ai_supplement",
        "authority": 0
      }
    ],
    "用户卖点锁定": [],
    "禁止变化项": []
  }
}
```

示例中的 `authority: 0` 是结构占位；真实条目只使用用户来源 3、产品图事实 2 或 AI 补充 1。

## 5. 自动继续

完成视觉分析后，不向用户增加产品卡确认步骤。把分析字段一次性写入 `product.productAnalysis`；Step 2用它约束产品身份和禁止变化项，Step 4只提取已验证事实，不调用任何旧后端提示词工作流。新产品图片统一写入`product.productImages`；`product.images`只用于读取旧任务。用户明确沿用原视频产品时写入`product.useBenchmarkProduct=true`，避免Step 5把空产品引用误判为遗漏。

若用户在提交前主动纠正产品信息，仅将纠正用于修正对应的图片识别事实，然后重新运行构建器；不得直接手改已序列化 JSON。

图片原文件不进入任何产品分析API请求。后续仅在Step 5使用灵智工坊上传本地素材时，按 `SKILL.md` 取得用户明确聊天同意和系统授权；官方Seedance CLI直接读取本地参考图。
