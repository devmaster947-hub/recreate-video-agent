# UGC 带货视频

## 定位

用于创建单条或批量 UGC 带货视频。

仅负责：

1. 检查产品图并保守提取产品信息。
2. 收集并确认用户输入。
3. 上传参考文件。
4. 调用内置 CLI。
5. 按确认数量生成 1～10 条独立创意视频，最多同时运行 3 条视频工作流。
6. 将每条视频的多个片段分别按顺序拼接。
7. 展示全部成功结果和单条失败信息。
8. 记录任务开始与结束余额，展示本次消费积分和剩余积分。

视频创意、视频脚本、Prompt 生成和模型策略均由后端工作流处理。不得在本地补写、改写或优化这些内容。

## 用户确认规则

- 先检查用户是否提供了至少一张产品图。未提供时，只提示用户先上传产品图，不提前询问其他配置。
- 收到产品图后，先自动补全产品信息，再与视频信息和额外创作需求一起按固定结构展示。
- 对每个存在多个选项的配置项，完整展示全部可选项，并等待用户明确确认后再提交。
- 用户尚未确认的选项不得提交，即使该选项有默认值。
- 可一次集中展示待确认项，减少往返。
- 所有确认和选择都优先使用简短的编号选项，让用户可以只回复一个或少量数字。
- 不得要求用户输入或复述“确认默认配置”“开始制作”“允许上传到某服务”等固定句子。
- 首次展示完整配置时，在末尾提供 `[1] 使用以上默认或已选配置并继续` 和 `[2] 修改配置`。用户回复 `1` 即视为明确确认四段配置；用户回复 `2` 后，只针对需要修改的字段继续提供编号选项。
- 用户已经在自然语言中明确指定部分配置时，保留这些选择，只让用户用编号确认其余默认项，不要求重新逐项输入。
- 如平台要求对第三方上传单独取得明确授权，使用 `[1] 允许上传并继续` 和 `[2] 取消`，将用户回复的编号作为明确选择，不要求复述授权语句。
- 不要求用户提供视频脚本。
- 用户明确确认四段配置后，立即上传文件并开始生成；不再展示“最终提交配置”汇总，不得要求用户额外回复“开始制作”或进行第二次确认。
- 待上传文件、参考图、片段数量和输出文件等运行信息可作为非阻塞的进度说明，不得用于再次请求确认。

### API Key 获取提示

- 优先使用环境变量 `LINGZHI_API_KEY` 或已保存的 Skill 配置；已有有效 API Key 时不得再次向用户索取。
- 仅在环境变量和 Skill 配置均无有效 API Key 时，才请求用户提供灵智工坊 API Key。
- 请求用户提供 API Key 时，必须同时提醒用户可前往 [灵智 AI Studio](https://studio.lingzhiai.com.cn/) 获取。
- 不得在回复、日志或错误信息中回显用户提供的 API Key。

配置项必须按如下结构展示，用自动提取的产品信息替换占位内容：

```text
1. 产品信息：
   - 产品名称：{自动生成}
   - 核心卖点：{最多 3 个}
   - 目标国家：{自动生成；无法判断时让用户补充}
   - 目标受众：{自动生成}

2. 视频信息：
   - 视频类型：[1] 原创 UGC（默认）/ [2] 剧情带货
   - 视频模型：[1] seedance-2-mini（默认）/ [2] seedance-2-fast / [3] google-omni / [4] grok-imagine-1-5-preview
   - 视频时长：默认15 秒，可选 4–60 秒
   - 生成视频数量：1 条（默认，可选 1–10 条）

3. 达人图：[1] AI 自动生成（默认）/ [2] 指定达人图
4. 额外创作需求：[1] 无（默认）/ [2] 补充需求

确认：
[1] 使用以上默认或已选配置并继续
[2] 修改配置
```

不要只展示默认项。

## 输入参数

### 产品信息

要求用户先提供产品图片，再根据产品图保守补全并让用户确认：

- 产品图片：必填，至少一张。
- 产品名称：必填；优先读取图中可见的品牌、品类或型号，无法确定准确商品名时使用可靠的通用品类名称。
- 核心卖点：最多 3 个；只使用图中可见信息或可靠的品类特征。
- 目标国家：结合图中语言、包装标识和用户上下文保守判断；无法判断时让用户补充”。
- 目标受众：根据可靠的产品品类和可见用途简洁补全，不添加无法支持的人口属性。

将上述自动补全结果标明为可修改，并在上传或提交前取得用户确认。不得虚构成分、认证、疗效、销量或其他无法从产品图和用户上下文证实的信息。

### 视频信息

完整展示并确认：

- 视频类型：原创 UGC (默认) / 剧情带货
- 视频模型：`seedance-2-mini`（默认） / `seedance-2-fast` / `google-omni` / `grok-imagine-1-5-preview`。
- 视频时长：4～60 秒，默认 15 秒；将 15 秒作为默认值展示并由用户确认。
- 生成视频数量：1～10 的整数，默认 1；将 1 条作为默认值展示并由用户确认。数量不合法时，只要求用户重新选择 1～10。
- 批量中的所有视频统一使用已确认的视频类型、模型、时长、达人图和额外创作需求；每条视频的创意和口播由后端独立生成。

视频类型映射：

| 用户选择 | `videoStyle` |
|---|---|
| 原创 UGC | `ugcProductDemo` |
| 剧情带货 | `storyDrivenAd` |

选择“自动选择”时，不得在本地替用户或后端选择上述风格；按现有 CLI 契约提交自动选择状态，由后端工作流决定。

### 达人图（可选）


如果用户指定达人图：先上传图片，再使用 `creatorMode: "referCreator"`，并把上传结果写入 `creatorImages`。

如果未提供，则由AI自动生成：使用 `creatorMode: "auto"`，`creatorImages` 为空数组。

### 创作需求（可选）

使用编号询问：

```text
[1] 无额外创作需求
[2] 补充创作需求
```

可补充：

- 指定场景。
- 指定风格。
- 指定拍摄方式。
- 指定保留或避免的内容。

创作需求只用于传递额外要求。视频创意和脚本由后端工作流自动生成。不要要求用户填写视频脚本。用户未提供或选择跳过时，`creativeRequirement` 传空字符串。

## 请求参数

仅保留以下顶层字段，不新增字段：

- `productBrief`
- `userConfig`
- `creativeRequirement`
- `creatorBrief`

生成视频数量只用于本地控制工作流循环次数，不是请求字段。不得将数量写入 `userConfig`，也不得新增 `videoCount` 或其他顶层字段。

### `productBrief`

根据用户提供的产品信息和产品图片上传结果构建：

```json
{
  "productName": "",
  "sellingPoints": "",
  "targetCountry": "",
  "targetAudience": "",
  "productImages": [
    {
      "url": "",
      "mimeType": "",
      "expiredAt": ""
    }
  ]
}
```

使用用户最终确认的产品信息；用户修改自动补全结果时，以用户提供的值为准。

### `userConfig`

根据用户确认的视频配置构建。示例中的值仅表示结构，不得作为未确认的选择：

```json
{
  "videoModel": "seedance-2-mini",
  "duration": 12,
  "videoStyle": "ugcProductDemo"
}
```

### `creativeRequirement`

传递用户补充的创作要求；未提供时传空字符串。

### `creatorBrief`

根据用户确认的达人图方式构建。AI 自动生成：

```json
{
  "creatorMode": "auto",
  "creatorImages": []
}
```

指定达人图：

```json
{
  "creatorMode": "referCreator",
  "creatorImages": [
    {
      "url": "",
      "mimeType": "",
      "expiredAt": ""
    }
  ]
}
```

`creatorMode` 仅允许：

- `auto`：由后端工作流生成达人参考图，`creatorImages` 传空数组。
- `referCreator`：使用用户指定的达人图，`creatorImages` 填写上传返回的 `url`、`mimeType` 和 `expiredAt`。

## 积分记录与展示

- 用户确认生成配置后、第一次调用上传或生成服务前，调用 `scripts/lzstudio_cli.py` 的 `get_credit_balance()` 查询并记录 `startBalance`。余额查询是只读操作，不需要单独确认。
- 全部视频工作流结束后，无论全部成功、部分失败或全部失败，都再次调用 `get_credit_balance()` 查询 `endBalance`。将结束余额查询作为收尾步骤执行，不得因前序阶段失败而跳过。
- 当开始和结束余额均为有效数值时，计算 `consumedCredits = startBalance - endBalance`。不得根据模型标价、片段数量或经验估算实际消费。
- 最终答复必须展示：

```text
积分：
- 本次消费：{consumedCredits} 积分
- 剩余积分：{endBalance} 积分
```

- 如开始余额查询失败但结束余额成功，展示剩余积分，并将本次消费写为“无法核算（未取得开始余额）”。
- 如结束余额查询失败，将剩余积分写为“无法查询”，本次消费写为“无法核算（未取得结束余额）”。简要展示已脱敏的查询错误，但不得泄露 API Key。
- 余额差额是账号级统计。如果同一账号在本任务期间还有其他灵智工坊任务并发运行，仍展示差额，但注明该数值可能包含并发任务的消费。
- 查询余额失败不得阻止或取消用户已经确认的视频生成任务。

## 工作流程

### 1. 收集并确认用户信息

先检查用户是否提供至少一张产品图。如果没有，只请求用户先上传产品图，在收到图片前不询问视频配置、达人图或额外创作需求。

收到产品图后，先保守提取产品名称、最多 3 个核心卖点、目标国家和目标受众。再按“用户确认规则”中的固定四段结构，一次性展示产品信息、视频信息、达人图和额外创作需求，并在视频信息中显示生成视频数量。完整展示所有多选配置，并在末尾提供 `[1] 继续`、`[2] 修改`。用户回复 `1` 后使用默认的 1 条直接上传与生成；用户回复 `2` 后只询问需要修改的字段。生成视频数量必须是 1～10 的整数。不得要求用户复述固定确认语句，也不得再请求“开始制作”或“确认提交”。

确认后，先按“积分记录与展示”查询并记录开始余额，再使用 `scripts/lzstudio_cli.py` 中的 `upload_file()` 上传每个本地产品图片和用户指定的达人图。只使用上传返回的 HTTP(S) URL，并保留 `url`、`mimeType`、`expiredAt`。

产品图片必须上传且每个本地文件只上传一次，上传结果由全部视频复用。达人图仅在用户选择“指定达人图”时上传，并同样只上传一次、由全部视频复用。

### 2. 调用 CLI 生成视频相关提示词

设用户确认的生成视频数量为 N。创建 `video_01` 到 `video_NN` 共 N 个独立视频工作流。每个工作流分别使用 `submit_sales_video_prompt()` 提交一次，并使用 `poll_sales_video_prompt()` 轮询同一任务 ID。每次提交且仅提交：

```json
{
  "productBrief": {},
  "userConfig": {},
  "creativeRequirement": "",
  "creatorBrief": {}
}
```

所有工作流使用相同的已确认请求参数，但必须独立提交提示词任务，让后端分别生成不同的视频创意和口播。不得把生成视频数量写入请求。

后端工作流返回：

- 视频 Prompt。
- 达人图 Prompt。

直接使用后端返回结果。不得在本地生成、补写、改写或优化 Prompt，也不得在本地制定视频创意、脚本或模型策略。

按 `video_01`、`video_02` 等编号分别记录提示词任务 ID。最多同时运行 3 条完整视频工作流；N 大于 3 时，任一工作流结束后再启动下一条。任务处于等待或处理中时不得重复提交。

### 3. 调用 CLI 生成参考图片（可选）

在每条视频工作流内，根据该条视频的后端结果，按需使用 `submit_image()` 和 `poll_image()` 生成：

- 达人图：仅当用户未提供达人图且该条视频的后端结果要求生成时；不同视频分别使用各自的达人图 Prompt。
- 分镜图：仅当后端工作流要求时。

用户指定的达人图由全部视频复用；AI 自动生成的达人图和分镜图归属于对应视频，不跨视频复用。图片 Prompt 和图片模型均直接使用各自后端工作流返回值，不在 Skill 内生成或选择。按视频编号记录每个图片任务 ID；生成任务只提交一次并使用同一任务 ID 轮询。

### 4. 调用 CLI 生成视频

在每条视频工作流内，对该条后端返回的每个视频片段，使用 `submit_video()` 和 `poll_video()` 生成视频。模型、Prompt、片段时长及其他生成配置直接使用该条后端工作流返回或确认的值。

上传并作为视频生成参考图传入：

- 必须：产品图片。
- 可选：用户上传或 AI 生成的达人图。
- 可选：分镜图。

只传入上传或生成结果中的公网 URL。按视频编号分别记录每个片段的任务 ID 与片段顺序；每个片段只提交一次，等待或处理中不得重复提交。

生成 1 条视频时，按原规则保存为 `segment_01.mp4`、`segment_02.mp4` 等。批量生成时，在对应的 `video_01/`、`video_02/` 等目录内保存 `segment_01.mp4`、`segment_02.mp4` 等。

### 5. 多段视频处理

每条视频只生成一个片段时，直接将该片段作为该条最终视频。生成多个片段时，仅将同一视频工作流内的片段按编号顺序调用：

```bash
python3 scripts/merge_video.py \
  --inputs segment_01.mp4 segment_02.mp4 segment_03.mp4 \
  --output final_video.mp4
```

生成 1 条视频时，最终文件保持为 `final_video.mp4`。批量生成时，最终文件分别保存为 `video_01/final_video.mp4`、`video_02/final_video.mp4` 等。不得调整片段顺序，不得跨视频拼接片段或最终文件。

### 6. 展示结果与积分

- 全部成功：按视频编号依次展示所有最终视频；如有参考图，也可按所属视频一并展示。
- 部分失败：继续完成其他视频，保留并展示全部成功结果，同时按视频编号展示失败阶段和已脱敏的错误信息。
- 单条视频任一必要阶段失败后，停止该条视频的后续阶段，释放并发名额后继续下一条；不得自动重试、改写 Prompt、替换模型或取消其他视频。
- 全部视频工作流进入终态后，按“积分记录与展示”查询结束余额并在最终答复中展示本次消费积分和剩余积分。即使没有成功生成任何视频，也必须执行该收尾步骤。

## 边界

不得在 Skill 内：

- 生成或改写视频 Prompt、达人图 Prompt、分镜图 Prompt。
- 编写视频脚本。
- 设计剧情或视频创意。
- 在确认阶段之外分析或改写目标受众与目标国家；确认阶段只允许根据产品图和用户上下文保守补全并等待用户确认。
- 虚构成分、认证、疗效、销量或其他无法证实的产品信息。
- 决定或替换模型策略。
- 新增请求字段。

所有智能创作与策略逻辑均交给后端工作流。
